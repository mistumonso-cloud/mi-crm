# AGENTS.md

Guía operativa para agentes de código (Codex, Cursor y otros) en este repositorio.
Para la referencia completa, consultar `CLAUDE.md` (fuente de verdad del proyecto).
Mantener este archivo SINCRONIZADO con `CLAUDE.md`: toda regla nueva se escribe primero
allá y luego se refleja aquí. Si divergen, gana `CLAUDE.md`.

**Proyecto:** Vibe Coder CRM

---

## Reglas Absolutas (resumen)

1. **MODO PLAN PARA TAREAS NO TRIVIALES**: tareas de 3+ pasos o con decisión de
   arquitectura → plan primero, con pasos de ejecución y de verificación. Si algo se
   rompe, PARAR y replanificar.
2. **BUCLE DE MEJORA CONTINUA**: todo error de sesión se registra en
   `.claude/memory/gotchas.md` (fecha, categoría, causa raíz, regla preventiva). Con 3+
   ocurrencias se promueve a Error Crítico en `CLAUDE.md`.
3. **VERIFICACIÓN ANTES DE DAR POR HECHO**: nada se marca completado sin prueba
   verificable (checks, logs, flujo real en navegador para UI).
4. **IDIOMA CONTEXTUAL**: prosa, commits y docs en español; identificadores técnicos en
   inglés.
5. **SIN REFERENCIAS A IA**: sin "Co-Authored-By", sin "Generated by" ni atribuciones de
   IA en commits, código, docs o PRs.
6. **POLÍTICA DE DECISIONES**: stack, arquitectura y dependencias mayores las decide el
   dueño del proyecto. El agente presenta opciones con pros y contras.
7. **CORREGIR LO PROPIO, REPORTAR LO PREEXISTENTE**: los fallos introducidos por el
   cambio se corrigen dentro del cambio; la deuda preexistente se reporta sin ampliar el
   alcance.
8. **TRABAJAR SIEMPRE EN RAMA**: `main` solo recibe cambios por PR con checks en verde.
   Prefijos: `feat/`, `fix/`, `refactor/`, `docs/`, `chore/`, `hotfix/`, con el número de
   ticket de Linear cuando exista (`feat/mis-N-slug`).
9. **NUNCA HACER PUSH SIN APROBACIÓN EXPLÍCITA**: commits locales sí; push y PRs
   requieren confirmación del dueño del proyecto, sin excepciones.
10. **SYNC DEL REPO AL INICIO**: `git fetch origin && git pull --rebase` al comenzar la
    sesión.
11. **VALIDAR ANTES DE PUSH**: correr localmente los checks del proyecto (ver Comandos).
12. **NUNCA BAJAR VERSIONES / ÚLTIMA ESTABLE**: sin downgrades; salvo Next.js (fijado a
    propósito, ver nota arriba), todo se usa en su última versión estable.
13. **SIN SECRETS EN EL REPO**: credenciales solo en `.env.local`/`.env.test.local`
    (gitignored) o en los secrets de GitHub Actions. Secreto filtrado = rotar de
    inmediato.
14. **SEGURIDAD DE DATOS (Convex, no RLS)**: toda query/mutation nueva de `convex/*.ts`
    que toque datos sensibles llama `requireRole`/`requireUser` (de
    `convex/lib/authz.ts`) como primera línea, sin excepción.
15. **VERIFICAR UI DE PLATAFORMAS ANTES DE INSTRUIR**: no dictar pasos de dashboards
    externos desde memoria; verificar con docs oficiales actuales o captura del usuario.
16. **GESTIÓN DEL TRABAJO VÍA ISSUES**: issue en Linear (equipo `MIS`) en "In Progress"
    antes de tocar código; el PR la referencia para cerrarla al merge.
17. **UNA PREGUNTA A LA VEZ**: nunca preguntas en lote; encadenar pregunta → respuesta →
    pregunta.
18. **SKILLS OBLIGATORIOS**: cargar el skill del dominio antes de tocar su superficie
    (tabla en `CLAUDE.md`).

## Errores Críticos — NO Repetir

Ver la lista completa y con ejemplos de código en `CLAUDE.md` → "Errores Críticos". Los

`npm run build`/Railway tras tocar `convex/*.ts`.

## Comandos Esenciales

```bash
# Sincronizar
git fetch origin && git pull --rebase

# Flujo rama + PR
git checkout -b feat/mis-N-slug
# ... cambios + commits ...
git push origin feat/mis-N-slug        # solo con aprobación (regla 9)
gh pr create --base main --title "..." --body "..."

# Validación local (ANTES de push)
npx tsc --noEmit
npm run lint
npm run build
npx playwright test
```
